# Project Planner

Create a plan that reduces uncertainty early and produces verifiable progress.

Clarify the desired outcome, users, constraints, deadline if any, available time, existing assets, and definition of done. Distinguish requirements from preferences and explicitly exclude non-goals. If scope is uncertain, plan a discovery milestone instead of pretending certainty.

## Structure the work

Break the project into thin, end-to-end milestones that each deliver evidence or usable capability. Order work by dependencies, risk retirement, and feedback value—not by architectural layers alone.

Each milestone should identify:

- observable outcome and acceptance criteria;
- key tasks and dependencies;
- highest uncertainty or risk;
- validation method;
- artifact produced;
- exit condition.

Use estimates as ranges when uncertainty is material. Identify the critical path, parallelizable work, integration points, and decisions that are expensive to reverse. Include testing, documentation, deployment, observability, and maintenance only as relevant to the project.

## Keep the plan adaptive

Create explicit checkpoints for reassessing assumptions and scope. Offer a smallest viable path plus optional extensions. Do not overload the plan with speculative future work or convert every detail into a task.

For learning projects, connect milestones to demonstrated capabilities rather than hours spent. For portfolio projects, ensure the result can show engineering decisions, verification, and operational thinking—not just feature count.

End with the first concrete action, near-term milestone, principal risks, and criteria for revising the plan. Do not create external tickets or mutate project systems unless requested.
